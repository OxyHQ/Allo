# Encryption

Allo encrypts every conversation, direct or group, as one MLS group
(RFC 9420). Each installation of the app is its own cryptographic instance
with its own Ed25519 key and its own leaf in every group it is in; the
backend stores and relays ciphertext and never holds a key that opens any of
it. This page says what runs and points at the pages that say how. The
static-ECDH design this replaced is described only in the ADR's "what is
replaced" table.

## What runs

**MLS, through `CryptoEngine`.** `@allo/core` wraps the `ts-mls` library
behind one interface (`packages/core/src/crypto/engine.ts`). Ciphersuite
`MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519`; a leaf's credential names
`accountId:instanceId`; every key package an instance publishes is signed by
its long-lived instance key. Adds, removes and updates are commits that rotate
the group secret, so an instance that is removed holds nothing for the next
epoch. Text, edits, deletions, reactions, read receipts, typing and the
group's name are all application messages inside the group: the server sees
none of them. The crypto provider is pure JavaScript on every platform and
never calls `crypto.subtle`, because Hermes has no WebCrypto and one provider
means one key format. All of it, including the invariants the library does
not enforce and the SDK does, is [Allo Platform cryptography](./platform/crypto).

**The instance model.** The first instance on an account is active at once;
every later one is pending until an existing active instance signs its id,
its public key and a server-issued challenge, after the user has compared the
challenge's fingerprint. The approval and the challenge are published, so any
client verifies an account's whole approval chain from the listing before it
adds a leaf, and never on the server's word. Every request that touches a
conversation carries an Ed25519 signature over the method, path, timestamp
and body hash, so a stolen Oxy token alone cannot act inside one. Revoking an
instance refuses its signature, cuts its sockets, and has a remaining leaf
commit its removal. Sections 6 and 7 of the crypto page.

**Joining by yourself.** Every commit's author also uploads, in the same
request, the MLS GroupInfo of the new epoch (`external_pub` plus the ratchet
tree; nothing secret, and nothing the server did not already hold). A device
that is a member with no leaf — a new account's first device, a new device of
a member — fetches it and joins by an external commit of its own, so nobody
else has to be online; a device that lost its group state but kept its key
replaces its own leaf the same way. Who gets in is decided by the members,
not by the server: each one verifies the joiner's credential against the
account's approval chain before the library sees the commit, and a forged
joiner is dropped with the state untouched. A conversation from before stored
GroupInfos still waits for another device to add it, and the app says which
is happening. Section 5 of the crypto page.

**Media.** A file is encrypted on the device with a fresh random key under
AES-256-GCM, uploaded as an opaque blob under an unguessable id, and the key,
nonce and digest travel only inside the encrypted `media` message; a
thumbnail is a second blob under its own key, named by the same message. The
server checks size and digest and nothing else. Section 4 of the crypto page.

**History for a new device.** A new instance is a new MLS leaf and decrypts
live traffic from its Welcome onward; old messages reach it as an encrypted
archive of decrypted timelines and media keys, never as group state. Two
paths, both end to end. A transfer: the device that added the new instance
to the account's groups offers its archive once, chunked and encrypted under
a fresh key that is HPKE-sealed to the new instance's X25519 transfer key,
with the manifest signed by the donor; the new instance accepts on its own
only after verifying, from the listing and never from the server's word,
that the donor is an active instance of the same account whose approval
chain checks out and whose key signed the manifest. A backup: one archive
per account under a key derived from a 12-word recovery phrase
(BIP39 → HKDF-SHA256 bound to the account id), shown once and stored
nowhere; a wrong phrase is refused before any download by a key check, and
the writing instance's signature is verified before import. The server
stores chunks (`blobs`), `history_offers` and `account_backups`, keeps a
chunk while an offer or the backup names it and a day after, and opens none
of it. Delivery receipts are encrypted messages like read receipts. Sections
12 to 16 of the crypto page.

**Storage on the device.** Everything the SDK persists (group states, key
package private halves, decrypted timelines, the outbox, media keys) is
encrypted at rest with AES-256-GCM under a random storage key kept in the
platform secret store, namespaced by app, account and instance. Section 8 of
the crypto page.

What the server does and does not see, the actors it is designed against, and
the acceptance tests of the issue are in the
[threat model](./platform/threat-model).

## Known gaps

These are properties the engine does not yet have. Each has a place in the
[roadmap](./platform/roadmap).

- **Losing every device and the recovery phrase loses history.** The server
  holds chunks under a key it never had and cannot help. A backup that was
  never enabled is the same loss. The phrase alone is not enough either:
  restoring needs an active instance, so a device awaiting approval restores
  after it is approved, and only the first instance on an account with none
  left can restore at once.
- **The recovery phrase approves nothing.** Trust on first use for the first
  instance is unchanged: when an account has no active instance, whoever
  holds a valid Oxy token becomes the root of the approval chain, and that
  window includes a user who lost or revoked every device. A recovery
  mechanism that could approve instead is designed and not built.
- **A stolen phrase plus an active instance reads the whole backup.** The
  key check is verified on the device, so nothing on the server notices or
  rate-limits a phrase being tried. `disable()` from any active instance
  deletes the server copy.
- **The elector offers history once, ever, per new device.** An offer that
  expired unconsumed after seven days is not repeated on its own;
  `client.history.offerTo` from any active device makes a new one.
- **A revoked instance keeps the current epoch until a remaining leaf commits
  the Remove.** It no longer receives events from the server, but ciphertext
  of that epoch it obtains by other means is readable to it until then.
- **The approval chain cannot be verified from outside when an approver was
  revoked**, because another account's listing carries active instances only.
  Such an instance is refused rather than trusted.
- **No fingerprint comparison between accounts.** The chain proves an
  instance belongs to an Oxy account id; that the account is the person the
  user thinks it is remains Oxy's and the user's problem.
- **`ts-mls` is unaudited**, single-maintainer and pure TypeScript. The spike
  checked protocol behaviour, not side channels. OpenMLS and mls-rs remain to
  be compared on device.
- **Metadata and traffic analysis are not hidden**: membership, timing,
  sizes (in 256-byte steps), presence and the existence of typing traffic are
  visible to the operator.
- **Malicious JavaScript on the web origin** runs with the page's authority
  and can use the keys. CSP and Trusted Types are designed, not built.
- **No per-account typing attribution, no push previews, no key package
  pruning.** Listed with what the tree does instead in section 10 of the
  crypto page.
- **A compromised endpoint reads plaintext after decryption.** Encryption is
  end to end, not end to eye.

## Where the code is

`packages/core/src/crypto/` (engine, provider, request signing and the chain
check, at-rest cipher, the transfer key, archive chunking, the backup key),
`packages/core/src/history/` and `backup/` (export, import, offers, the
backup lifecycle), `packages/core/src/sync/` and `outbox/` (epoch gating,
pending commits, the queue), `packages/backend/src/middleware/instanceAuth.ts`
and `services/platform/` (the server's half, `historyService.ts` and
`backupService.ts` included). The wire contract is
[API v1](./platform/api-v1).
