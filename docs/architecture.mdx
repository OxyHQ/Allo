# Architecture

Allo is a three-workspace monorepo managed with Bun. The split is intentional and strict: nothing in the frontend imports from the backend, and the only shared surface is `@allo/shared-types`.

## Workspaces

```
packages/
  shared-types/   @allo/shared-types   TS-only, built first via postinstall
  frontend/       @allo/frontend       Expo Router app (iOS / Android / Web)
  backend/        @allo/backend        Express + Socket.IO + MongoDB
```

Root `package.json` declares `workspaces: ["packages/*"]` and orchestrates with `bun run --filter`:

```sh
bun run dev                # all workspaces in parallel
bun run dev:frontend       # @allo/frontend only
bun run dev:backend        # @allo/backend only
bun run build              # build all
bun run build:shared-types # rebuild types (runs on postinstall too)
bun run typecheck          # backend then frontend, no emit
bun run test               # all workspaces
```

A root `lint` script exists but is not usable: the backend declares no `lint`, and `shared-types` declares one without shipping eslint or a config. Only the frontend lints.

## Dependency graph

```
@allo/shared-types  ◀── @allo/frontend
                    ◀── @allo/backend
```

`shared-types` has zero internal deps. Both `frontend` and `backend` consume its compiled `dist/` output (the `postinstall` script in the root `package.json` makes sure the build is always fresh after `bun install`).

External shared deps both halves pull from npm:

- `@oxyhq/core` — auth client + types. Its `/server` entry point supplies the backend's auth, CORS and rate-limit middleware.
- `@oxyhq/contracts` — shared API contracts
- `@oxyhq/services` — RN auth context (frontend only)
- `@oxyhq/bloom` — UI primitives (frontend only)
- `@oxyhq/crowdsource*` — moderation pipeline (backend only)

## Frontend

`packages/frontend/` is an Expo SDK 57 app (React Native 0.86, React 19.2) using Expo Router for file-based routing. Highlights:

| Area | Module |
|------|--------|
| Routing | `app/` (Expo Router 57, typed routes) |
| Styling | NativeWind 5 preview (Tailwind for RN) + Bloom theme tokens |
| State (UI) | Zustand stores in `stores/` |
| State (server) | Custom hooks in `hooks/` over the offline-aware API client in `lib/api/` |
| Encryption | `lib/signalProtocol.ts` + `stores/deviceKeysStore.ts` |
| Offline cache | `lib/offlineStorage.ts` + `lib/offlineQueue/` (AsyncStorage) |
| Secure storage | `lib/secureStorage.ts` (wraps `expo-secure-store`) |
| Real-time | Socket.IO client (`lib/network/`) |
| P2P | `lib/p2pMessaging.ts` (WebRTC data channels; not functional) |
| Matrix | `lib/matrix/` — client port for the [migration](./matrix/client-strategy). Nothing imports it yet. |
| i18n | `lib/i18n.ts` + `locales/` (en, es, it) |
| Notifications | `expo-notifications`. The token POST has no server route — see [Push](#push-notifications). |

### Responsive layout

Breakpoints live in `constants/responsive.ts`:

- `< 768px` — single-pane stack
- `768 - 1023px` — list + thread two-pane
- `>= 1024px` — list + thread + contact details three-pane

One file does all three: `app/(chat)/_layout.tsx` reads both breakpoints and switches component trees at each boundary. The thread route it renders into is `app/(chat)/c/[id].tsx`; there is no `app/c/` group and no second layout.

### Stores

Zustand-backed stores in `stores/`:

| Store | Responsibility |
|-------|---------------|
| `messagesStore` | In-memory + AsyncStorage-persisted decrypted message cache, keyed by conversation id. |
| `conversationsStore` | List of conversations + denormalized last-message + unread counts. |
| `deviceKeysStore` | Local device key bundle (public + private), regen / rotation triggers. |
| `usersStore` | Resolved user profiles fetched from Oxy. |
| `appearanceStore` | Theme mode + accent color. Mirrors backend `UserSettings.appearance`. |
| `chatUIStore` | Transient UI: active conversation, draft text, scroll position. |
| `messagePreferencesStore` | Per-conversation font size, density, mute state. |
| `conversationSwipePreferencesStore` | User-customized swipe actions. |

State that needs to survive launch goes through Zustand's persist middleware over AsyncStorage; ephemeral UI state lives in plain Zustand.

## Backend

`packages/backend/` is a single Express app + a Socket.IO server attached to the same HTTP server. Entry point is `server.ts`.

```
src/
  config/       CrowdSource moderation configuration
  models/       Mongoose schemas
  routes/       Express routers mounted under /api
  services/     the moderation pipeline (CrowdSource intake, outbox, workers)
  types/        backend-only TS types
  utils/        helpers (database connect, logger, push, etc.)
  __tests__/    vitest suites, run against a real MongoDB replica set
```

There is no `middleware/` directory: auth, CORS and rate limiting all come from `@oxyhq/core/server`.

### Mongoose models

| Model | What it stores |
|-------|---------------|
| `Conversation` | `direct` or `group`, participants[], unreadCounts, lastMessage, archivedBy |
| `Message` | Ciphertext, senderDeviceId, encryptionVersion, encryptedMedia[], readBy, deliveredTo |
| `Device` | Public key bundle (identity key, signed pre-key, one-time pre-keys) per `(userId, deviceId)` — unique index |
| `UserSettings` | Per-user appearance, privacy, security (cloudSync toggle), profile customization |
| `Block` / `Restrict` | Per-user block + restrict lists |
| `PushToken` | Expo / FCM tokens for push delivery. Nothing writes to it — see [Push](#push-notifications). |
| `UserBehavior` | Per-user UX preferences / analytics counters |
| `Report` | Account reports filed by users |
| `ModerationEvent` / `ModerationOutbox` | The CrowdSource moderation pipeline's event log and transactional outbox |

There is **no `User` model**. Identity is delegated to Oxy. The backend trusts the `req.user.id` populated by `@oxyhq/core`'s `oxy.auth()` middleware and stores everything keyed by that Oxy user id.

### Authentication

```ts
import { oxyClient } from "@oxyhq/core";
import { createOxyAuthMiddleware } from "@oxyhq/core/server";

// Public routes
publicApiRouter.get("/health", (req, res) => res.json({ status: "ok" }));

// Authenticated routes
app.use("/api", publicApiRouter);
app.use("/api", createOxyAuthMiddleware(oxyClient), authenticatedApiRouter);
```

`createOxyAuthMiddleware` validates the incoming `Authorization: Bearer <jwt>` against the Oxy API, populates `req.user = { id, ... }`, and rejects with 401 if the token is missing or invalid. Both routers mount on `/api`; the public one is registered first, so `/api/health` is reached before the auth middleware runs.

There is no optional-auth middleware. Every route is either fully public or fully authenticated.

### Real-time

The Socket.IO server lives on the same HTTP server. The `/messaging` namespace is the primary surface; the main namespace is reserved for ambient connection tracking.

Connection authentication mirrors REST — the client sends `{ token, userId }` in `socket.handshake.auth`. The middleware in `server.ts` populates `socket.user = { id }`; unauthenticated sockets are disconnected on connect.

Each authenticated socket auto-joins `user:<userId>`. The client then sends `joinConversation` / `leaveConversation` to subscribe to per-thread rooms. The server broadcasts `newMessage`, `messageUpdated`, `messageDeleted`, and `typing` into the conversation room.

### Security middleware

Allo writes none of its own. `server.ts` applies three middlewares from `@oxyhq/core/server`:

- `createOxyCors({ appOrigins })` — the Oxy apex family (`*.oxy.so`) is admitted automatically; `appOrigins` adds the two local dev origins. The allowlist is a literal in `server.ts`, not an environment variable.
- `createOxyRateLimit(oxyClient)` — resolves the session and applies per-user rate limiting in one pass, mounted before the API routers.
- `createOxyAuthMiddleware(oxyClient)` — described above.

Separately, a guard early in the chain answers requests with `503 Database temporarily unavailable` when Mongo is not connected, rather than letting them fail as 500s, so clients can retry.

### Push notifications

`utils/push.ts` can deliver through Firebase Admin, but nothing reaches it. The frontend posts its device token to `/notifications/push-token`, and **no notifications router is mounted**, so the call 404s and no `PushToken` document is ever created. `sendPushToUser` reads a collection that stays empty, and no route calls it. Push is inert on both ends.

## Where this is going: Matrix

Allo is migrating to Matrix, and this architecture is what it migrates off. The
design lives in [`docs/matrix/`](./matrix/data-model) and deliberately precedes
implementation.

Nothing above has changed yet. The REST + Socket.IO transport, the Mongoose
models, and the encryption in [Encryption](./encryption) are all still what runs.

The one piece of Matrix code in the tree is `packages/frontend/lib/matrix/`, a
client port: an interface (`types.ts`) that may not import a Matrix SDK, a
native implementation over `@unomed/react-native-matrix-sdk`, and a web half
that throws `MatrixPlatformUnsupportedError` rather than pretending to work. No
screen, hook or store imports any of it; its only callers are its own tests.

Two spikes validated the decisions behind it. `spikes/matrix-web/` is complete
and documented; of `spikes/matrix-rn/` only the generated `android/` project is
committed, so the Android run it performed cannot be reproduced from the repo.

## Shared types

`packages/shared-types/` is a plain TypeScript package. `bun run build` emits `dist/` and the `postinstall` script in the root runs `bun run build:shared-types` so the latest types are always present after `bun install`. Both frontend and backend `import { … } from "@allo/shared-types"`.

## Build & deploy

| Target | Command | Output |
|--------|---------|--------|
| Web | `bun run build:frontend` | `packages/frontend/dist/`, published to Cloudflare Pages (project `allo-frontend`) by `.github/workflows/deploy-frontends.yml` |
| iOS | `eas build --platform ios` in `packages/frontend/` | EAS-managed `.ipa` |
| Android | `eas build --platform android` in `packages/frontend/` | EAS-managed `.aab` |
| Backend | `bun run build:backend` | `packages/backend/dist/`. Shipped as a `linux/arm64` image built from `packages/backend/Dockerfile`, pushed to ECR and rolled out on AWS ECS by `.github/workflows/deploy-aws.yml` — see [the backend README](https://github.com/OxyHQ/Allo/blob/main/packages/backend/README.md#deployment). |
